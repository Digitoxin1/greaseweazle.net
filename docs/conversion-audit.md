# Conversion Audit: Python/C -> VB.NET (Greaseweazle)

This document is the executive summary of the Python/C to VB.NET conversion
audit for the unified `gw-vb` project. It folds together:

- **Structural parity** (file-level Python -> VB mapping)
- **Symbol parity** (per-symbol mapping with the four-status taxonomy)
- **Behavioural fixture runner** (`src/Greaseweazle.Parity/Greaseweazle.Parity.vbproj`)
- **Behavioural spot-checks** of the highest-risk subsystems

The companion machine-readable artifact is
[`docs/conversion-audit.json`](conversion-audit.json) (regenerated by
`python tools/audit_conversion.py`).

The companion per-symbol checklist is
[`docs/parity-checklist.md`](parity-checklist.md) and the legacy
strict-name view is
[`docs/parity-symbol-manifest.md`](parity-symbol-manifest.md). Both are
regenerated by the same audit tool and are now fully consistent with this
report.

### 2.2 Notable splits and orphans

- **`usb.py` -> 3 VB files** (`UsbProtocol.vb`, `UsbUnitClient.vb`, `SerialPortTransport.vb`). Intentional separation of wire protocol, client, and transport.
- **`tools/util.py` -> 5 VB files**. The shared parts (`TrackSet`, `ColumnFormatter`, `OptionParser`) live in the `Greaseweazle.Shared` namespace. The action-orchestration helpers (`find_port`, `get_unit`) bind into `tools/Tooling.vb` and `usb/UsbUnitClient.vb`.
- **`flux.py` + `optimised/__init__.py` -> 7 VB files**. `FluxModel.vb` is the managed flux container; `optimised/*.vb` are managed ports of the C extension.
- **`tools/list_ports_windows.py` -> `tools/WindowsPortDiscovery.vb`**. Pure managed replacement for the `ctypes` Windows port enumeration. Companion port-scoring helpers live in `Tooling.vb` / `BasicActions.vb`.
- **`tools/TrackResolution.vb`** is the single intentional orphan-vb file: it has no Python 1:1 counterpart and centralizes default-track resolution shared by `read`, `write`, `convert`, `erase`, `align`. The author flagged this in the file with `' Python map: no-1:1 with Python symbols`.
- **14 empty `__init__.py` files** - none of them contain any code, so they have no VB counterpart by design.
- **0 pure orphan-py** (every non-empty Python file has at least one VB file referencing it via a `Python map:` comment).

## 3. Symbol parity (Phase 2)

The audit tool uses a four-status taxonomy:

- `mapped-exact` - a `' Python map: <py_module>::<symbol>` comment in VB binds this Python symbol to a specific VB declaration. **Highest confidence.**
- `mapped-normalized` - no `Python map:` comment, but a unique normalized name match exists in the scoped VB file (snake_case -> PascalCase, `__init__` -> `New`, `__str__` -> `ToString`). **Medium confidence.**
- `name-only-ambiguous` - multiple normalized matches, no binding comment. **Low confidence.**
- `missing` - no exact and no normalized match.

| Status | Count |
|---|---|
| `mapped-exact` | **779** |
| `mapped-normalized` | 0 |
| `name-only-ambiguous` | 1 |
| `missing` | **6** |

| method    | 522 | 517 | 0 | 1 | 4 |

The seven non-`mapped-exact` symbols are all members of the legacy
`image/hfe.py::HFETrack` v1 wrapper (`HFETrack`,
`HFETrack.{__init__, from_bitarray, from_hfe_bytes, to_hfe_bytes}`,
`HFE.hfev1_get_image`, `hfev3_mk_track`). They were intentionally removed
from the VB tree during the dead-code sweep documented in §6 because the
v1 read/write paths are folded directly into `Hfe.DecodeHfeBits` /

`Hfev3Generator` state machine. The audit tool reports them as
`missing` / `name-only-ambiguous` because the `Python map:` comments
were retired alongside the bodies; nothing about the runtime behaviour
of the HFE format is missing — see §5.5 for the full HFE/IPF spot-check.

- **PASS** - logically equivalent (idiomatic VB differences are allowed).

## 6. Red-flag list (status: all resolved or explicitly clarified)

The original audit raised 11 concrete fix targets. Each one is reproduced
below with its current state and the commit-time evidence:

1. **`IBMFixedCodec.vb` :: `CreateMfmMasterTrack`** — **RESOLVED.** Final
   `mfm_encode` NRZI pass added after gap fill; matches `ibm.py:421-422`.

2. **`IBMFixedCodec.vb` :: `IbmTrackFixedDef.MkTrack`** — **RESOLVED.**
   Per-sector sizes are now built in physical order and permuted into
   sector-ID order via `sec_map`, matching `ibm.py:from_config`.

3. **`HFEImage.vb` :: double-step semantics** — **RESOLVED.** `ApplyDoubleStep`
   removed; `EmitTrack` no longer mutates the bit stream. The `double_step`
   header byte is the only signal, exactly like Python.

4. **`HFEImage.vb` :: `BuildHfeV3TrackBytes` / `GetImageV3`** — **RESOLVED.**
   Full `HFEv3_Generator` ported as a dual-head state machine; opcode escape,
   dynamic `Bitrate`, multi-`Index`, `Rand`, and `Nop` padding all in place.
   The previous `Hfev3Op` / `Hfev3Generator` stubs are gone; both are now
   real types bound to Python via `Python map:` comments.

5. **`UsbUnitClient.vb` :: `Seek`** — **RESOLVED.** TRK0 sample, optional
   `NoClickStep` + flippy-drive consultation, `ErrorHandling.Check`, then
   `Head` — mirroring `usb.py:Unit.seek` end-to-end (including older-firmware
   `CmdError` tolerance for `GetCurrentDriveInfo`/`NoClickStep`).

6. **`TrackModel.vb` :: `MasterTrack.BuildFlux`** — **RESOLVED.** The
   `splice < 4` branch now uses `Math.Max(0, bits.Count + (Splice - 4))` so
   that `bits[:self.splice-4]` and `bit_ticks[:splice]` end-relative
   semantics are preserved.

7. **`UsbUnitClient.vb` :: `New` / `UsbOpen`** — **RESOLVED.** `Unit.New`
   now calls `Reset()` inside a defensive `Try/Catch` so the first
   `GetInfo` cannot misframe against a stale serial buffer.

8. **`IBMFixedCodec.vb` :: `IbmTrackFixed.DecodeMfmFlux`** — **CLARIFIED.**
   Python's *raw-level* decoder appends a `Sector` even when the IDAM CRC
   is non-zero, but the *fixed-level* decoder immediately filters those
   sectors out (`if r.idam.crc != 0: continue`). VB's fixed-level decoder
   gates at the same point; net behaviour is identical and an inline
   comment in `DecodeMfmFlux` records this design choice.

9. **`CAPSImage.vb` :: `IpfTrack`** — **RESOLVED.** Real `IpfTrack` class
   that inherits `MasterTrack`, implements `HasVerify`, exposes `Sectors`,
   `Tolerance`, `VerifyRevs`, an iterator-based `StrongData(sector, weak)`,
   and a `VerifyTrackImpl` that performs PLL-based windowed search per
   strong-data segment. `IPF.GetTrack` now wires `track.Verify = track` and
   `track.Sectors = data` like Python.

10. **`IBMFixedCodec.vb` :: `from_config` extras** — **RESOLVED.** Ported:
    dynamic `gap3` autosize with `MFMGaps.gap3[n>=4] = 255` cap (and the
    matching FM cap), ED rate forces `gap2 = 41`, `gap4a` is halved when the
    track exceeds the budget, and the `oversized` flag is now tracked on
    `IbmTrackFixed`. Auto rate-selection mirrors Python's `range(1,4)` MFM
    sweep and `range(0,2)` FM sweep.

11. **Cosmetic / low-risk parity items** — **ALL RESOLVED** (each via the
    fixes above):
    - `MasterTrack.ToString` leading newline.
    - `Precomp.ToString` integer formatting (`Math.Truncate` mirrors Python `%d`).
    - `PllTrack.ToString` newline / hex-literal style.
    - `PllTrack.GetAllData` returning live arrays.
    - `IpfTrack.StrongData` is now the real Python iterator.
    - `Td0Lzss.Unpack` final-byte difference on truncated input is documented
      as intentional VB-side hardening (no behavioural exposure).

12. **`IBMTrack_Fixed.raw` second-pass reconcile** (`ibm.py:657-681`) —
    **RESOLVED.** `IbmTrackFixed.DecodeFlux` no longer resets `_sectorValid`
    at the top of each call, every per-sector data write is gated on
    `Not _sectorValid(idx)` (Python's `s.dam.crc != 0` precondition for
    update), and unmatched good-CRC IDAMs are deduplicated into an
    encounter-ordered list and reported via
    `T<cyl>.<head>: Ignoring unexpected sector C:.. H:.. R:.. N:..`
    (one print per unique `(C,H,R,N)` tuple) at the end of the call —
    exactly matching `ibm.py:657-681`. `Align.AlignTrack` now calls

    instance across PLL retries, so the cumulative first-good-wins
    reconcile actually has somewhere to accumulate, mirroring
    `align.py:131-135`'s `dat.decode_flux(flux, pll)`.
